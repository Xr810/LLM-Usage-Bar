# T21:让 router 第一次真的处理一个请求

> **先读 [`README.md`](README.md) 的铁律。** 依赖:T17 已合并(后端完全体)。
>
> **这不是写功能的任务,是验证任务。** 到今天为止 router 的每一次验证都是
> 假上游、假凭据、内存库 —— 1256 个测试验的全是零件。**它从没处理过一个真实请求。**

---

## 0. 现状:为什么现在没人能验(2026-08-15 实测)

| 事实 | 后果 |
| --- | --- |
| `/Applications/LLM Usage Bar.app` 是**旧构建**(PID 58380 在跑) | 里面没有任何 router 代码 |
| **前端没做** | 那九个 tauri 命令**没有任何调用方** |
| 线上库 `~/.llm-usage-bar/llm-usage-bar.db` **没有 router 表** | 它还停在旧 schema |
| `~/.codex/config.toml` 里有 `[model_providers.packyapi]`(含 bearer token) | 凭据在文件里,不在 app 的凭据体系里 |

**所以「点一下界面试试」这条路不存在。** 你要自己搭出验证路径。

---

## 1. 三条安全红线(违反任何一条,成果作废)

1. **不许改用户真实的 `~/.codex/config.toml`。** 那是他每天在用的 Codex 配置,
   写坏了他的 Codex 就用不了。要测指针写入,**复制一份到临时目录去测**。
2. **不许动线上库 `~/.llm-usage-bar/llm-usage-bar.db`。** 里面是真实用量数据,
   而且它还停在旧 schema —— 一跑迁移就回不去了。**要用就先复制一份。**
3. **不许用用户的真实凭据去调付费接口,除非你先问过他并得到明确同意。**
   `config.toml` 里那个 bearer token 是真的,打出去是真花钱。

---

## 2. 要证明什么(按价值排序,能证几条算几条)

| # | 命题 | 为什么重要 |
| --- | --- | --- |
| 1 | **router 能在真实端口上起来并接住一个真实 HTTP 请求** | `start()` 至今没有生产调用方,只在测试里被调过 |
| 2 | **候选队列 → 改写 model → 注入凭据 → 转发 → 流式回传**整条链路通 | 这是 T4/T5/T6/T9/T11 五个任务的交汇点,从没一起跑过 |
| 3 | **`router_attempts` 真的记上了 provider_id** | 分账的地基 |
| 4 | **token 真的被回填**(T13 的 SSE 扫描) | 它只在假流上验过,真实上游的 SSE 长什么样没人见过 |
| 5 | **schema 从旧版本迁到 v28 不丢数据** | 线上库还在旧版本,用户升级时会真的跑这条链 |
| 6 | **Codex 本体真的能把请求打进来** | 需要写指针 + 重启 Codex,受红线 1 约束 |

**第 1–4 条你应该能独立做到**(自己起 router、自己发请求、自己查库)。
**第 5 条用线上库的副本做。**
**第 6 条需要用户配合**,做不到就如实说,不要为了凑齐而去动他的 config.toml。

---

## 3. 方法你自己定,但要满足两条

- **必须走真实的 `route::server::start()`**,不许绕过它自己拼一个简化版
- **必须查真实的 `router_attempts` 表**,不许只看日志

可选的做法(不限于这些):写一个 `#[ignore]` 的集成测试用 `cargo test -- --ignored` 跑;
写一个临时的 example/bin;把 app 构建出来跑。**选哪条在报告里说明理由。**

上游用什么由你定:本地假上游(不花钱、不碰凭据)能证明第 1–4 条的大部分;
真实 packyapi 更有说服力但受红线 3 约束。**建议先用假上游跑通,再问用户要不要打真的。**

---

## 4. 交付

不走常规格式,交这五样:

1. **你选了什么方法,为什么**
2. **第 2 节六条命题,逐条给出「证明了 / 没证明 / 怎么证的」**,附实际输出
   (HTTP 状态码、`router_attempts` 的真实行、token 数值)
3. **过程中发现的任何接缝问题** —— 这是本任务最值钱的产出。
   零件各自都有测试,但**它们从没一起跑过**,接缝上的问题只有这时候才会暴露
4. **你碰了哪些用户的真实文件**(应该是「只读了 config.toml 的结构」这种程度)
5. **还差什么才能让用户自己点一下就验**(这直接决定前端先做哪块)

**跑不通比跑通更值钱。** 跑不通说明零件之间有个接缝所有人都没看到,
**如实报告失败,不要修**——修法要项目所有者定。
