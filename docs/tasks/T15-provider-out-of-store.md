## 0. 先读这一节,否则你会做一件既做不到也不该做的事

模块化设计 §9.3 说「`database/` 里 12 个文件提到 Codex」。**那个数字把三类完全
不同的东西混在了一起**,2026-08-14 实测:

| 类别 | 处数 | 能不能动 |
| --- | --- | --- |
| **测试夹具**(`tests.rs` 109、`usage_events.rs` 18、`agent_modules.rs` 12…) | 约 170 | **不动。** 测试当然要写具体 provider 名,这不是耦合 |
| **冻结的历史迁移**(`schema.rs` 里绝大部分、`migration.rs`) | 约 45 | **绝对不动。** 老数据库里就存着 `proxy_takeover_codex` 这类键名,改掉就是把用户的库迁坏 |
| **真正的耦合** | **十几处** | **这才是你的范围** |

**所以本任务的目标不是「让 grep 数归零」。** 谁要是把测试夹具或迁移里的字符串
改掉让数字变好看,成果直接作废。

---

## 1. 你的范围:四处

### 1.1 `schema.rs:890` 的 CHECK 约束

```sql
app_type TEXT PRIMARY KEY CHECK (app_type IN ('claude','codex','gemini'))
```

**这是真耦合**:加一个 agent 要改 schema、要写迁移。而 `agent_modules` 表里
本来就有一份 agent 清单。

改法:**新建迁移 `migrate_v28_to_v29`,把这个 CHECK 去掉**(SQLite 改约束要走
「建新表 → 拷数据 → 删旧表 → 改名」,照抄仓库里现有同类迁移的写法)。

**去掉约束不等于不校验** —— 校验上移到写入侧:插入前确认 `app_type` 在
`agent_modules` 里存在。**这一条必须有测试**:写一个不存在的 app_type 要被拒。

### 1.2 `providers_seed.rs` 的内置目录(5 处)

这是**数据**不是逻辑,内置目录里有 provider 名字是正常的。
**但它现在是硬编码的 Rust 字面量。** 改成:数据仍留在这个文件里,但**收进一个
明确命名的常量表**(如 `BUILTIN_PROVIDER_CATALOG`),并在文件顶部写一句注释说明
「这里是数据,不是 core 认识 provider —— 加一家在这张表里加一行」。

**不要把它挪到别的层、不要改数据内容。**

### 1.3 `usage_providers.rs` 的 5 处生产代码

逐处判断:是「core 认识某一家」还是「参数恰好叫这个名字」。
**前者要拆,后者不要动。** 报告里逐处说明你的判断和理由。

### 1.4 `agent_provider_bindings.rs` 的 3 处、`providers.rs` 的 1 处

同 1.3,逐处判断。
