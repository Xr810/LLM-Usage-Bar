## 0. 一句话

**材质 + 可关的透明 + 一套主题系统。** 目标从「跟系统设置无法区分」换成
「一个有识别度的第三方 Mac app」,参照物是 Raycast。

---

## 1. 目标为什么换

HIG 改造计划把目标定在「跟系统设置无法区分」。那个目标能保证不出错,但它的
天花板是**正确但寡淡** —— 连做三轮之后仍然是这个结果,用户三次说「太丑」。

Apple 自家 app 不做主题选择器;Raycast 做。用户一路要的是后者。这个前提换掉之后,
下面几条才成立。**这是一次有意的取舍,不是对 HIG 计划的否定** —— 那份计划里关于
语义字号、continuous 圆角、系统控件、无障碍矩阵的部分全部继续有效。

## 2. 定了的四条

| # | 决定 |
| --- | --- |
| V1 | **整窗一层 `.regularMaterial`,但半透明可关。** 关掉不落到白底,落到选定主题上 |
| V2 | **系统「降低透明度」开启时自动切到不透明主题。** 原本是无障碍降级分支,现在是产品功能——不再需要为它单画一套 |
| V3 | **强调色由主题定**,但内置一套叫「系统」的主题跟随 `Color.accentColor`,**默认就选它**。默认行为仍然是苹果那套,想要识别度的人自己去换 |
| V4 | **外观(主题、半透明)归「通用」分区**,不在路由那一屏。它是全 app 的外观,不是路由的配置 —— 位置对应 Raycast 的 General → Appearance。路由那屏只留:模型映射 / 凭据 / 接管 / 模式与分账 |
| V5 | **起步两套主题(一浅一深),不是三套。** 两套差别不明显的浅色不如一套明确的——`Overcast` 与 `Sage` 并排看几乎分不出,先只留 `Overcast` + `Ink` |

## 3. 颜色规则:标记实体,不标记导航

来自 Raycast 设置窗的观察:侧栏上面那组(General / Launcher / Shortcuts / Advanced /
About)图标**基本是灰的**,下面那组(AI / Calendar / Clipboard History / Developer)
才是高饱和彩色。区别是——上面是**设置分区**,下面是**一个个实体**。

落到本项目:

- **四个 tab 图标一律灰**,只有选中那个上强调色。~~第三轮让 Claude Design 把四个
  tab 全做成彩色圆角方块~~ —— 那条按这个标准是做反了
- **饱和色只留给 provider 身份点**(实体)与**状态符号**
- 数据区(映射表、分账表正文)不取色

身份色**每主题一个值**,不是一个常量:深色下 `#5856D6 → #5E5CE6`,否则在深底发闷。
调色板顺序:indigo / orange / purple / teal / pink / brown,按注册顺序分配、可改。
green / yellow / red 保留给状态,纯蓝避开(默认强调色)。

系统色的浅深 hex 值见 Claude Design 项目里的 `#t0b` 色卡,逐个核对过是真值。

## 4. 行的处理:靠对比,不靠行高

**这条推翻了我自己前一轮的诊断。** 之前判断「太密所以难看,行高得抬」,实测
Raycast launcher 的行高约 38pt,比我方案的 40pt 还紧。它的透气来自三处:

1. **同一行里两级文字对比拉得很开** —— 主要文字全亮,次要压到 ~52%
2. **元数据一律靠右对齐**,中间留出大段空白
3. **面板外围留白大**,行内其实很紧

结论:**「好看」和「信息全」的取舍有一半是假的**。压暗次要文字 + 右对齐元数据
能同时拿到两样。base URL 与协议降到第二行,不占第一列的视线。

其余从 Raycast 设置窗搬的:分组表单行(标签左、控件右、组内细分隔线)、分区标题
上方留大间距、**选中态是极淡的半透明高亮**(不是强调色带子)、底部常驻操作条带键帽提示。
需要「看图选择」的设置才用卡片 —— 对应物是**自动/手动模式切换**。

## 5. 保留不动的

三轮设计里真正值钱的不是皮,换皮不影响这些,全部保留:

- 接管 Codex 的 **diff 预览**(摊开将写入 `~/.codex/config.toml` 的原文、删除行带
  删除线、备份承诺、在访达中显示)
- 重启提醒是**常驻横条**不是 toast
- 分账列头 `输入 ≥ / 输出 ≥` 与「计数不完整」的表达
- 空态直接说后果(「路由对所有请求返回 503」),不说「暂无数据」
- 手动模式常驻可见;被拉黑那家仍可选,缺凭据那家不可选
- 模式切换器切换的是**下面那块区域本身**:自动=排序列表带拖动把手,手动=点选启用

## 6. 与 HIG 改造计划的关系

**被取代的**:§1.1「`primary()` 靛蓝 → `Color.accentColor`」这条现在归 V3;
§5.1 待拍板项「品牌靛蓝 vs 系统强调色」已由 V3 回答。

**继续有效的**:P0 的 lint 脚本(三条硬规则不变,只是「禁止字面 RGB」的例外从
`NativeDesignSystem.swift` 改成「主题定义文件」)、P1 的语义字号刻度与 4 档
continuous 圆角、P2 设置窗用系统 `Form`、P5 的验收矩阵 —— **矩阵要乘上主题数,
所以 V4 限制起步只做两套**。
