为什么现在做便宜

HIG 计划 P1 本来就要重建 token 层,而 SwiftUI 那 14 个视图还没写。让 token 走一层主题结构是边际成本;等界面写完再抽才是返工。

贵在哪

不在管道,在设计出几套都好看的主题,以及验收矩阵乘上主题数。所以起步两浅一深,不要一上来做八套。

身份色要跟着变

provider 身份色在深色下要换成深色变体(#5856D6 → #5E5CE6),否则在深底上发闷。上面三张里已经这么处理了。

强调色归属(已定)

HIG 计划 §5.1 原本定的是「交互元素跟随用户的系统强调色」。有了主题之后这条撞车,现已裁定。

主题定(Raycast 的做法):三套主题各自带强调色,视觉最统一,代价是不跟随用户在系统设置里选的颜色。
系统定:主题只管底色和中性灰,强调色永远读 accentColor,更"苹果",但主题的识别度弱一半——因为最扎眼的那个颜色不归它管。

已定(2026-08-23):主题定,但内置一套叫「系统」的主题跟随 accentColor,默认就选它。两边都不放弃,默认行为仍然是苹果那套,想要识别度的人自己去换。
